# AI Intelligence - 2026-11-28

## Daily Executive Summary

1. **Google 将八个 Workspace MCP 服务列为 GA，并公布 2027 年 agent 接入规则。** 从 2 月 1 日起，AI agent 访问 Workspace 数据必须走 MCP；直连 REST 的 agent 只能用 Standard Tier 配额。政策尚未生效，团队已有迁移和费用评估窗口。[来源](https://developers.google.com/workspace/release-notes)
2. **Qwen Code 0.28.7 加强跨实例恢复，同时取消内置循环上限。** 恢复更完整，失控保护也更依赖外部预算和 kill switch。[来源](https://github.com/QwenLM/qwen-code/releases/tag/v0.28.7)
3. **LiteLLM 1.108.19 LTS 修复断流假成功与工具路由错误。** 这类错误会绕过 fallback 或卡住 agent，升级前仍需跨 provider canary。[来源](https://github.com/BerriAI/litellm/releases/tag/v1.108.19)
4. **Ming-Image 0.2 Design 开放 6B 权重与代码。** 它面向文字密集设计和图层拆分，但 80 GiB 参考配置与初步榜单要求先做实际 brief 测试。[来源](https://huggingface.co/inclusionAI/Ming-Image-0.2-Design)
5. **GigaChat4 开放 708B 总参数、41B 激活参数的模型家族。** 公开产物完整，但验证成本极高且独立证据有限，当前只适合 WATCH。[来源](https://huggingface.co/ai-sage/GigaChat4-708B-A41B)

## Models

Ming-Image 0.2 Design 提供 MIT 权重、代码与可运行配置，适合用真实海报和 UI brief 验证文字准确率与图层可编辑性。GigaChat4-708B-A41B 公开 FP8、BF16、GGUF 与 checkpoint，但 708B 总参数让独立验证成本很高。Kandinsky ImageSR 2.0 也开放了 2x/4x 超分权重；它没有独立 benchmark，应只做自有素材对照。

## Agent & AI Engineering

### LiteLLM 1.108.19 LTS（TRIAL）

最重要的变化是把“上游已经断了却报告成功”改为可触发 fallback 的错误。中途断流（mid-stream abort）指响应已经开始发送后连接失败；难点是客户端若收到正常 stop，就会保留半截答案并跳过备用 provider。工具 ID、thinking signature、护栏和费用记录也应一起回归。

## Developer Tools

### Qwen Code 0.28.7（TRIAL）
