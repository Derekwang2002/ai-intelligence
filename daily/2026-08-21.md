## Agent & AI Engineering

- **Agentic retrieval 的工程含义**（见 Executive Summary 的 Mistral 事件）：当检索变成「模型驱动的多步文档操作」，RAG 管理重点从 chunking 策略转向工具面设计与索引新鲜度；对文档密集领域（财报、合同、合规）收益最大，简单直接查询仍适合 one-shot RAG。隔离边界设计（索引在自有周界内）是企业数据的关键卖点。
- **量化 × agent 记忆的隐藏交互**（详见 Research）：agent 工作区大量依赖「长、可更新、语义密集」的上下文（记忆系统、可编辑文档、tool-state）——正是 INT4 量化前摄干扰损失最大的场景。部署量化开源模型跑 agent 的团队应在验收时加入「覆写-召回」探针。
- **推理模型 API 的成本耗尽防御**（详见 Research 的 SMTrap）：攻击者无需探测目标即可合成高推理量查询——限流与查询模式检测的假设被削弱。最低成本防线：每请求 token/成本上限 + 给模型求解器类工具（把搜索卸载出上下文）。
- Codex `codex queue` 的编排含义（详见 Developer Tools）：跨会话消息 + idle 唤醒让「编排者 → 多个常驻会话」的模式在 stable CLI 里可用——社区 orchestration-on-CLI 模式（趋势 #3 判据 (b)）的原料进一步齐备。
