# AI Intelligence - 2026-11-16

## Daily Executive Summary

1. **Qwen Code 0.27.4 开放受控本地访问，并收紧 Auto Mode 授权。** 稳定版加入临时目录授权、带认证的托管 Web Terminal，以及飞书和企业微信 webhook。远程执行和企业消息更好接入，但目录授权时长、破坏性操作审批与消息丢重仍需回归。
2. **Qwen Concept 27B 把有争议的权重编程变成可下载、可对照的实验。** 发布方公开权重、代码、评测数据和范数匹配的随机对照，并报告 GPQA、LiveCodeBench 与 thinking token 改善。结果尚无独立复现，因此从 IGNORE 调整为限定范围的 TRIAL，而不是训练路线结论。
3. **Sophon-Realtime v1 公开全双工语音权重、代码和试用 API。** 32B 模型可在单张 80 GB GPU 上运行，并提供兼容 OpenAI Realtime 的三小时试用。0.25 秒首音频延迟和 benchmark 都由发布方报告，真实打断质量仍待复测。
4. **Inkling 2 Small 开放 100 万 token 多模态 MoE 权重。** Apache-2.0 模型有 594B 总参数、17B 激活参数，可通过 Tinker 和第三方 API 试用；原生 NVFP4 自托管至少需要 500 GB 聚合显存，硬件门槛很高。
5. **LiteLLM 1.108.9 向 LTS 回移推理与网关修复。** 更新覆盖混合 reasoning、Responses 缓存、Vertex 调用方标识及多条 provider 路由。仍在 LTS 的团队可减少与主线差距，但跨 provider 字段转换必须先做 canary 回放。

## Models

### Inkling 2 Small

MoE（混合专家）不会让每个 token 都经过全部参数，而是只激活少数专家。难点是“594B 总参数”不能直接当作每次推理的计算量；Inkling 2 Small 每个 token 约激活 17B 参数，但所有权重仍要占用显存。

### Sophon-Realtime v1

“全双工”指模型能一边说一边继续听，用户插话时还要及时停下并改写回应。难点不只是首音频快，还包括抢话检测、状态恢复和转写一致性；发布方 benchmark 尚不能替代真实对话回放。

## Research

### Qwen Concept 27B

“权重编程”不是继续用训练数据和梯度微调，而是直接计算并改写模型矩阵。难点是性能提升可能来自修改幅度、评测选择或偶然扰动；这次公开的随机对照和预注册子集让问题可检验，但仍需要独立复现。

发布方修改 Qwen3.5-27B 的九个 down-projection 矩阵，并公开 BF16、FP8、NVFP4 与 GGUF 产物。其自报结果包括 GPQA 提升 4.3 点、LiveCodeBench 提升 13 点，以及部分任务 thinking token 减少 27% 至 54%。
