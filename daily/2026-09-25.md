## Daily Executive Summary

- GPT-6 Sol/Luna 与 Claude Opus 5.5 同期把模型选型从“最强是谁”进一步推向“每个完成任务花多少钱”。两组模型都强调长上下文、工具调用和 agent 工作负载，但价格跨度很大，应以自家任务的完成率、步骤数和缓存命中率做路由。
- Cursor 把 coding agent 延伸到部署后：Rollouts 观察生产遥测并准备暂停或回滚，Security Review 在全代码库上下文里审 PR。能力边界越过 merge 后，审批和可撤销性必须跟着升级。
- GitHub、Qwen Code 与 PASTABench 从产品、运行时和评测三个方向指向同一件事：宽执行能力需要独立的沙箱、证明、遥测和介入时机。趋势 #7 因此由 emerging 升为 strengthening，置信度仍为 Medium。

## Models

- GPT-6 Sol 面向复杂编码与 agent，Luna 面向高吞吐任务。两者共享 105 万 token 上下文与内置工具，但标准输出价格相差 20 倍，适合做同一 harness 下的难度路由。
- Claude Opus 5.5 把输入/输出价降至每百万 token 4/20 美元，缓存读取降至 0.20 美元。METR 的发布前评估认为它对 AI 研发是渐进改进，不是能力跳变。

## Agent & AI Engineering

- Cursor 的生产测试给出一条可复用的 context 优化顺序：缩短稳定前缀、按需加载工具 schema、固定缓存边界、压缩文件行号，最后再用 subagent 隔离上下文。
- PASTABench 显示，最佳安全监控也只有 40.74% 的介入落在最佳窗口。安全 classifier 不仅要判对，还要在危险状态发生前判对。

## Open Source

## Research

- Anthropic 的约 950 个 Claude agent 用 21 小时筛查 20 多万个逆转录酶，候选经人类筛选后进入湿实验。目标系统的功能仍未知，这证明的是“agent 生成假设 + 人类实验验证”流程，不是自主科学闭环。
- SWE-Flux 用插桩测试生成 480 道仓库级运行时题，最佳模型准确率只有 37%。coding agent 会改代码，不等于它能解释跨过程数据流和程序状态。
- 英国 AISI 通过 EvalEval 发布带配置与方法的机读评估记录，为跨机构可复现披露增加了政府评估机构采用证据。
