## Daily Executive Summary

- **新事件：Cursor cloud agents 成为 always-on 系统（8/19，TRIAL）**——事件驱动 Subscriptions（订阅 PR / Slack thread / 定时任务，事件发生即唤醒；cloud agent 自动订阅自己创建的 PR 并驱动到完成：修 CI、处理 bot 评论）；subagent 可运行在各自独立 VM（项目隔离副本 + 干净上下文，支持 swarm 并行测试）；`/goal` 长期目标；follow-up 等待下一个 tool call 的非打断式 steering。这是目前 always-on multi-agent runtime 模式最完整的商业封装，与 Cursor 自家 Origin 托管 + CI 形成全链路闭环；代价是更深的云栈锁定与 swarm 算力成本。
- **新事件：PTXBench（arXiv 2608.17379，WATCH）**——首个下探到架构特定 PTX、同时覆盖 H100 与 B200 的 LLM kernel 优化 benchmark（GEMM + attention，三重度量：正确性 / 目标指令是否运行时执行 / 相对前沿库加速比）。关键负结果：指令被执行 ≠ 性能竞争力，没有任何被测模型能稳定追平前沿库；SFT 改造 Qwen3.6-27B 后泛化仍不均匀。kernel-agent 流水线应以加速比为成功信号。
- **新事件：LLM API 迁移的 item-level 回归（arXiv 2608.17719，WATCH）**——对 GPT-5.4 → GPT-5.6 Sol 三次成对升级做 900 条目 × 50 次查询的 FDR 受控审计：聚合 +7.3pp 的升级边里仍有至多 8.3% 的条目可靠回退；instruction following 上严格/宽松评分口径之差可达 3.9 点。方法论（逐条目采样 + 实际显著性阈值 + 归档发布）可直接复用为 API 迁移验收门禁。

## Agent & AI Engineering

- **事件驱动 agent 的工程含义**（详见 Developer Tools 的 Cursor 事件）：Subscriptions 把 agent 的触发模型从「人发起」扩展到「事件唤醒」（PR / Slack / 定时），自主驱动 PR 到完成意味着 agent 开始长期占用 CI/CD 环节——上线前需要预算上限、变更范围 guardrails 与失败回退策略。
- **API 迁移验收门禁**（详见 Research）：在被厂商强制迁移前，用逐条目采样 + 显著性阈值跑一遍自己的 golden set——聚合分数会掩盖双向的条目级变化。GPT-5.4 → 5.6 Sol 的实测显示净收益升级仍携带 8%+ 可靠回退。
- Gemini CLI 0.56.0 stable 中的一个 core 修复值得注意：**取消/中止时回滚整个 multi-turn request**——与昨日入库的 KV-cache 回滚一致性论文同一主题方向（请求层的整体回滚语义），生态正在各层补齐回滚语义。
