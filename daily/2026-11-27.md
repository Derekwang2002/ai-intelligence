# AI Intelligence - 2026-11-27

## Daily Executive Summary

1. **Qwen Code 0.28.6 为托管会话补上暂停与冷恢复。** 会话等待审批、提问或后台任务时可以停放，harness 冷启动后再恢复；event bus 也成为默认路径。当前证据只有 release notes，团队仍需用真实仓库做崩溃注入，确认 shell 和工具不会重复执行。[来源](https://github.com/QwenLM/qwen-code/releases/tag/v0.28.6)
2. **Nemotron 3.5 Parse 开放训练数据、微调方案与 DFlash2 加速模型。** 三套合成数据合计约 1,888 万样本，权重和方案均可下载。NVIDIA 在 H200 上报告单请求吞吐提升 7.62 倍、并发 512 时提升 1.52 倍，但速度和效果对比仍由发布团队完成。[来源](https://huggingface.co/blog/nvidia/building-on-nemotron-35-parse-open-data-fine-tunin)
3. **FlashInfer 的 NVFP4 注意力实现已经有部署证据。** 代码已合入，Reactor 报告在选中的世界模型调用中端到端延迟最多降低 15.34%。测试只覆盖 RTX Blackwell 的一种 GPU 系列，质量检查靠人工，不能把结果外推到所有形状和模型。[来源](https://developer.nvidia.com/blog/how-to-optimize-nvfp4-attention-on-nvidia-rtx-blackwell-through-register-recycling/)
4. **一项 7,660 条轨迹研究发现，编程 agent 通过测试后仍会留下多余改动。** 逐块撤销补丁并重跑测试后，11% 的代码单元被判为非必要；自动精简后仍有 89% 的补丁能解决任务。研究只覆盖一个 Copilot CLI harness，依赖任务测试与 LLM 评审，也没有公开代码或人工验证。[来源](https://arxiv.org/abs/2611.34875)
5. **llama.cpp 上线可复现的 AMD 性能看板。** 每周任务公开原始结果和工作流，并对提示处理、token 生成与上下文扩展各跑 10 次。首批只有 Radeon 8060S 与 AI Pro R9700S，适合做回归基线，不是 AMD 全产品线排行榜。[来源](https://huggingface.co/blog/ggml-org/llamacpp-amd-bench)

## Models

### Raon-1 mini（TRIAL）

KRAFTON 发布 30B-A4B 正式权重，采用 Apache-2.0，并提供 MXFP8、NVFP4、GGUF 与 DFlash2。它偏重韩语对话、搜索和工具调用；发布方 benchmark 尚无广泛独立复现，托管 API 也只在限期内免费。本条由召回自检补录，保留 11 月 24 日的实际仓库创建时间，不伪装成今日发布。

### Nemotron 3.5 Parse 资产（TRIAL）

公开资产包括 998 万图表样本、100 万表格样本、790 万多语 OCR 样本、微调方案、Parse v1.1 权重和 DFlash2 推测模型。推测解码是让小模型先猜一段 token，再由主模型批量验收；难点是命中率、并发与验证开销共同决定它是否真的更快。团队可在目标文档上直接复测解析质量、页吞吐和显存。

## Agent & AI Engineering

### Qwen Code 0.28.6（TRIAL）

本次更新改变的是长任务故障路径，而不是新增模型。停放表示会话在等待外部输入时不继续占用执行循环；冷恢复表示原 harness 已退出，新的进程仍能从持久状态接续。难点是恢复不能重复提交工具、副作用或已经排队的 shell 命令，因此发布说明不足以替代故障注入。

### Swarm 训练配方（TRIAL）

Hugging Face 公开一个 TRL 示例，让四个 agent 共享 Qwen3-0.6B 策略并按团队结果学习。演示在两张 H200 上训练约五小时，估算成本 50 美元；任务只是数字排序，因此它是可运行的研究基线，不是生产 multi-agent 提升证据。

## Open Source

### llm.asm（IGNORE）

这个 MIT 项目用 17,252 行 x86-64 汇编实现 Qwen3-0.6B 推理、裸机 runtime 与迷你 GPT 训练器。代码和一致性测试值得底层工程师研究，但单一小模型、自定义权重格式、作者自测和无生产支持使它不适合产品投入；社区热度没有被当成采用证据。

### llama.cpp AMD 看板（TRIAL）

看板公开原始数据、工作流与重复次数，适合检查版本升级后的性能回退。硬件只覆盖两套系统，不能据此比较整个 AMD 产品线，也不能替代目标主机上的质量与功耗测试。

## Research

### GRH Lean 短证明（WATCH）

研究团队公开约 30 万行的可读版与约 7.6 万行的压缩版，形式化黎曼猜想和 Dirichlet L-functions 的广义黎曼猜想。机器检查只能证明 Lean 项目在给定公理与依赖下类型检查通过；难点是形式化陈述是否准确对应数学命题、证明是否有隐藏的建模问题，仍需要数学家通读。仓库明确说明目前没有通读或论文。

### Agent 多余改动研究（WATCH）

Dynamic Relevance Analysis 会逐块撤销补丁并重跑任务测试，用来问“删掉这部分后任务是否仍通过”。难点是测试本身可能不完整，LLM 评审也不是人工代码审查；因此 11% 是这套判定方法下的结果，不是所有真实仓库的普遍比例。

### 监控攻击策略研究（WATCH）

研究发现，同一 agent 监控器的漏报率会随攻击生成方法和优化强度明显变化。攻击先在代理监控器上优化，再迁移到留出的 GPT-5.4 目标；代理轨迹是否代表真实攻击仍是开放问题，且没有公开代码。
