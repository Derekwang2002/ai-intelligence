### 1. Microsoft and Hugging Face expose ThinkingBox as a runnable stateful-agent benchmark

- **Disposition:** `new-event`.
- **Published:** `2026-10-03T22:56:48Z`, from the Hugging Face RSS item; the rendered joint Microsoft/Hugging Face post gives the date as October 3. Canonical source: [joint Microsoft/Hugging Face article](https://huggingface.co/blog/microsoft/thinkingbox). Supporting primary artifacts: [Microsoft ThinkingBox](https://github.com/microsoft/thinkingbox), [benchmark data](https://github.com/microsoft/thinkingbox-data), [OpenEnv adapter](https://github.com/huggingface/OpenEnv/tree/main/envs/thinkingbox_env), and [paper](https://arxiv.org/abs/2608.19741).
- **What is new:** the older paper and `thinkingbox-bench-v1.0` data release are now packaged as a runnable OpenEnv environment with pinned framework/data versions and an executable evaluator. The post reports 507 workflows, 20 independent attempts per workflow, and 121,680 valid trials in its common-set ablation. Of 79,853 failed attempts, 67.24% still ended cleanly after a state-changing tool call and without a final tool error; terminal-state checks found wrong values, extra effects, or missing effects. The harness and framework are MIT-licensed; benchmark data is CDLA-Permissive-2.0.
- **Why it matters:** this directly tests a production failure that transcript and tool-call graders miss: an agent can report success while leaving the database in the wrong state. It also separates `pass@1`, solved-at-least-once breadth, and literal 20/20 repeatability.
- **Caveats:** all workflows are synthetic reconstructions. The paper is older and the event should be framed as public runnable availability, not as a newly invented benchmark. Cost figures use a September 20 OpenRouter price snapshot rather than measured production invoices.
- **Suggested rating:** `TRIAL`. One-day action: run one workflow 20 times with a candidate model and compare `pass@1` with observed 20/20 while inspecting wrong, missing, and extra side effects.
- **Existing event match:** none found (`ThinkingBox`, `2608.19741`, and the paper title do not occur in `events/`, `index/`, `projects/`, `sources/`, or `reviews/`).

### 2. Google publishes a 4B local model for correcting speaker diarization

- **Disposition:** `new-event`.
- **Published:** repository `createdAt = 2026-10-04T13:06:04.000Z`; it was last modified before cutoff at `2026-10-04T15:14:52.000Z`. Canonical sources: [Hugging Face model API](https://huggingface.co/api/models/google/DiarizationLM-Gemma-4-E4B-v1), [model card](https://huggingface.co/google/DiarizationLM-Gemma-4-E4B-v1/blob/main/README.md), and [Google speaker-id implementation](https://github.com/google/speaker-id/tree/master/DiarizationLM).
- **What it is:** `DiarizationLM-Gemma-4-E4B-v1` post-processes ASR plus speaker-diarization output. Google supplies merged BF16 weights, two 4-bit GGUF files for llama.cpp/Ollama, Transformers usage, and Apache-2.0 licensing. It is trained over Fisher, Callhome, ICSI, and AMI rather than only two-speaker telephone speech.
- **Reported evidence:** the model card reports simultaneous WDER and cpWER gains against its USM + Turn-to-Diarize baseline on all four corpora with bootstrap intervals. WDER changes are 5.32→2.99 on Fisher, 7.74→4.92 on Callhome, 14.70→14.10 on ICSI, and 15.68→14.89 on AMI. The latter two test sets are only 3 and 16 meetings, respectively.
- **Why it matters:** a 4B model with ready-made GGUF artifacts makes speaker-attribution correction practical on local hardware; it also targets long-monologue identity drift that naive multi-domain fine-tuning can worsen.
- **Caveats:** the card explicitly says this is not an officially supported Google product. The benchmark is author-reported, no independent reproduction is supplied, downloads/likes were zero at first inspection, and the multi-speaker meeting evidence is small.
- **Suggested rating:** `TRIAL`. One-day action: replay a held-out meeting set through the published BF16 and Q4_K_M artifacts, measuring WDER/cpWER, latency, and whether long monologues retain speaker identity.
- **Existing event match:** none found.

### 3. Strata makes Qwen3.8-Flash-Next runnable on 12 GB gaming GPUs

- **Disposition:** `new-event`, `late_discovery: true` (repository predates the overlap but reached the recall surface during this run).
- **Published:** GitHub repository created `2026-09-24T16:40:20Z`; current-window HN discovery was `2026-10-04T12:51:53Z`. Canonical source: [Niko1221/Strata](https://github.com/Niko1221/Strata); repository metadata is available from the [GitHub API](https://api.github.com/repos/Niko1221/Strata).
- **What it is:** an MIT-licensed inference engine that distributes Qwen3.8-Flash-Next experts across GPU, system RAM, CPU, and SSD and exposes OpenAI- and Anthropic-compatible local endpoints. Its documented floor is a supported 12 GB GPU, 32 GB RAM, and roughly 80 GB SSD space—not literally “any consumer hardware.”
- **Reported evidence:** the README reports 94 output tokens/s for Q2_0 on an RTX 5070 with 64 GB RAM and 60 tokens/s on an RX 9070 XT with 47 GB RAM; author benchmark files are present, but no independent reproduction was found. The project had about 9.1k stars and 831 forks in the rendered GitHub page during the scan (GitHub API counts continued rising after cutoff).
- **Why it matters:** it is a concrete local-serving design for a very large sparse MoE, with one-click setup and agent-facing APIs. The rapid adoption signal is unusually strong for a repository created ten days earlier.
- **Caveats:** there are no GitHub releases, the benchmark is self-reported, first startup can lock 35–55 GB RAM, and aggressive Q2/IQ2 quantization needs task-quality testing. The “Coder” derivative retains only 91% of the authors' cited SWE-bench score and is weaker for CJK text.
- **Suggested rating:** `TRIAL`. One-day action: install on one representative 12–24 GB GPU host and compare Q2_0/IQ2_XS against the official endpoint on a fixed coding set, recording quality, TTFT, decode speed, RAM pressure, and restart behavior.
- **Existing event match:** none found.
