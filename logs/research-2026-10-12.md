## High-value new-event candidates

### 1. ESP32 iPhone Agent — recommended disposition: `new-event` / `WATCH`

- **Time basis:** GitHub API records repository creation at `2026-10-11T19:10:25Z`, inside the canonical window. The project has no tagged GitHub release, so the repository creation time is the cleanest first-public timestamp. [Repository API](https://api.github.com/repos/onehumanbeing/esp32-iphone-agent)
- **What shipped:** an MIT-licensed hardware/software loop that receives iPhone pixels over AirPlay/UxPlay, uses a vision model through an OpenAI-compatible API for planning/action selection, and sends taps, drags, typing, and keys through a roughly US$7 ESP32-S3 acting as USB HID. It does not require Xcode, a developer account, a signed phone-side app, or jailbreak. [Project README](https://github.com/onehumanbeing/esp32-iphone-agent)
- **Availability and requirements:** source is public; users need an ESP32-S3, an iPhone, macOS or Linux host, UxPlay/GStreamer, and either a cloud or local vision model. USB-C iPhones connect directly; Lightning devices need a camera adapter. The project is not a hosted service and has no price beyond user-supplied hardware/model costs. [Setup and hardware](https://github.com/onehumanbeing/esp32-iphone-agent#hardware)
- **Evidence boundary:** the README demonstrates a whiteboard drawing and alarm-setting flow and describes pointer correction, post-action screen-change checks, replanning, watchdog recovery, and debug traces. These are author demonstrations and implementation claims, not an independent benchmark. Landscape orientation, non-ASCII typing, lock/passcode/Apple Pay/DRM screens, and recalibration are explicit limitations. [Limitations](https://github.com/onehumanbeing/esp32-iphone-agent#limitations)
- **Adoption snapshot:** the GitHub API showed 274 stars and 32 forks when checked after the run cutoff. That is a discovery/adoption signal only; do not treat the post-cutoff count as the event timestamp or an independent validation result.
- **Why it matters:** it replaces the fragile Xcode/WebDriverAgent dependency with a cheap physical I/O bridge. That materially lowers the entry cost for real-device computer-use experiments and exposes a reusable closed-loop calibration design.
- **Why WATCH, not TRIAL yet:** source and hardware instructions are public, but reproduction requires specific hardware and a real phone, and there is no independent task suite or reliability result. Promote to TRIAL after one independent setup reproduces coordinate correction, missed-tap recovery, and emergency-stop behavior across several apps.
- **Dedup:** no match for `esp32-iphone-agent` or `ESP32 iPhone Agent` was found in `index/events.json`, `events/`, `projects/catalog.json`, or `sources/catalog.json`.

### 2. Agent Standup adds Codex session support — recommended disposition: `new-event` / `TRIAL`

- **Time basis:** stable `v1.27.0` was published at `2026-10-12T00:14:54Z`, inside the canonical window. Stable `v1.28.0` at `09:15:58Z` only adds an AI-drafted Korean localization and is not the substantive event. [v1.27.0 release](https://github.com/Atoll92/agent-standup/releases/tag/v1.27.0)
- **What changed:** the local VS Code/CLI/desktop viewer now reads Codex desktop and CLI session files from `~/.codex/sessions` alongside Claude Code sessions. It displays prompts, responses, commands and outputs, changed files, web/MCP calls, questions, reasoning summaries, token counts, and turn endings. It explicitly does not yet render Codex subagents or pictures. [Release notes](https://github.com/Atoll92/agent-standup/releases/tag/v1.27.0)
- **Availability and license:** MIT source, stable tagged release, VS Code extension, `npx` launcher, and standalone Node 18+ server are public. The project says it reads but does not write session files. [Project README](https://github.com/Atoll92/agent-standup)
- **Privacy boundary:** default English/local viewing stays on `127.0.0.1`; French translation, jokes, radio, and opt-in usage counting can call external services. The product shows sensitive command output and file content, and its video redaction does not mask spoken/quoted content, so exported clips require review. [Privacy and security notes](https://github.com/Atoll92/agent-standup#privacy--security)
- **Evidence boundary:** no independent accuracy or overhead benchmark was found. Token figures are read from session records, not estimates of billing. The repository had 144 stars and 20 forks when sampled after the run cutoff; that is a community signal, not validation.
- **Why TRIAL:** a team can verify it in under a day with public packages and one non-sensitive Codex/Claude session: confirm event ordering, command-output completeness, token accounting, localhost isolation, and whether exported redaction omits secrets.
- **Dedup:** no existing event, project, source, or briefing match was found for `Agent Standup`.

### 3. Littleguys publishes installable multi-agent control surface — recommended disposition: `new-event` / `TRIAL`, with `late_discovery: true`

- **Time basis:** stable `v0.1.0` was published at `2026-10-11T15:35:16Z`, inside the overlap but 27 minutes before the checkpoint; it was not found in the existing event store. Stable `v0.1.1` at `2026-10-11T21:24:58Z`, inside the canonical window, explicitly provides Homebrew and DMG installation and self-update. [v0.1.0](https://github.com/herval/littleguys/releases/tag/v0.1.0), [v0.1.1](https://github.com/herval/littleguys/releases/tag/v0.1.1)
- **What shipped:** an MIT macOS 13+ menu-bar app for chatting with agents, seeing status, approving/denying tool calls, and scheduling routines. It supports multiple OpenClaw gateways, Hermes, Claude Code, Codex, Gemini CLI, Goose, OpenCode, and ACP registry agents. [Project README](https://github.com/herval/littleguys)
- **Availability:** the release now names a Homebrew tap and downloadable DMG for Apple silicon and Intel and claims signing/notarization. That settles the earlier source-only/package-availability ambiguity, but this research did not independently execute the binary or validate notarization. [v0.1.1 release](https://github.com/herval/littleguys/releases/tag/v0.1.1)
- **Security and execution boundary:** Littleguys is a control surface, not a common execution sandbox. Scheduling durability depends on the underlying adapter; ACP routines run only while the app is open. It can store gateway device tokens, launch/configure agents, and approve commands, so teams must test credential handling and authorization per adapter. [Project documentation](https://github.com/herval/littleguys)
- **Evidence boundary:** no independent reliability/security evaluation was found. The repository had 23 stars and 3 forks at the later sample, so adoption remains early.
- **Why TRIAL:** on a disposable Mac profile, a one-day check can install the signed package, connect one local ACP agent, verify approve/deny behavior, inspect token-file permissions, and confirm which scheduler survives application exit.
- **Dedup:** no existing match for `littleguys` was found. Because the initial stable release is in the overlap and absent from prior decisions/storage, use `late_discovery: true` if persisted.
