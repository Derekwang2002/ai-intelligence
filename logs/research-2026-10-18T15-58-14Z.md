**Suggested handling:** `update-existing` → `ev-20260922-01`

- Official sources:
  - GitHub release: https://github.com/vllm-project/vllm/releases/tag/v0.32.0
  - PyPI artifact page: https://pypi.org/project/vllm/0.32.0/
- Public time and precision:
  - GitHub release `published_at`: `2026-10-18T06:50:48Z`.
  - First PyPI artifact inspected: `2026-10-18T10:03:29.256186Z`.
  - Both timestamps are inside the normal scan window.
- Stage and availability:
  - Stable tagged release, not a prerelease.
  - Installable from PyPI; official release also lists CUDA 12.9/13.0, ROCm, XPU, CPU, aarch64 and macOS artifacts plus Docker images.
  - Python requirement is now `>=3.11,<3.15`; Python 3.10 support is removed.
- Material changes worth carrying into the existing event:
  - Security defaults changed: CORS no longer accepts every origin by default; untrusted image inputs are restricted to raster formats; shared-memory multimodal cache handles are signed; JSON schemas deeper than 64 levels are rejected.
  - The release names three fixed advisories: `GHSA-4hhp-h66f-j5j7` (chat-template resource exhaustion), `GHSA-q97c-p368-75c4` (tokenizer `max_token_id`) and `GHSA-frvg-qw88-hww9` (P2P ZMQ socket exhaustion).
  - Model Runner V2 becomes the ROCm default. The release adds broader low-precision KV-cache paths, a GPU n-gram speculator, FlashInfer kernel pre-download/preload, and a shared-memory tensor arena.
  - Multiple API servers now choose the least-loaded worker. The release claims 43–85% more requests per second on very short Qwen3-0.6B requests; this is a project benchmark, not an independent production result.
  - The CPU wheel is present in the release artifacts, addressing the CPU-wheel gap called out in the previous run’s follow-up list.
- Key limits and upgrade risks:
  - This is a very large release: 814 commits from 363 contributors. The release notes include several breaking changes beyond Python 3.10 removal, including restricted CORS defaults, dependency floors, removed execution paths, a changed `max_tokens` interpretation, and renamed Responses API reasoning stream events.
  - Performance percentages in the release notes come from individual PR benchmarks on specific models and hardware. They should not be generalized to a user workload without regression tests.
  - Suggested next action: stage the upgrade with explicit origin configuration, multimodal input tests, Responses streaming contract tests, and representative latency/throughput traces before promotion.

  - GitHub release `published_at`: `2026-10-18T05:53:32Z`.
  - Both timestamps are inside the normal scan window.
- Stage and availability:
  - Stable version on PyPI and a non-prerelease GitHub tag.
  - Requires Python `>=3.10,<3.15`; GitHub release includes signed container verification instructions.
- Material changes worth carrying into the existing event:
  - Breaking security default: stdio MCP servers are disabled by default.
  - MCP boundary changes include upstream OAuth client-metadata identities, issuer binding, preservation of elicitation context, request-local guardrail credentials, and a fix that prevents forwarding the caller’s LiteLLM key to an MCP server.
  - Identity and secret-management work includes Anthropic workload identity federation, OpenAI workload identity federation in the admin flow, encryption at rest for guardrail/search-tool parameters, and a `LITELLM_FIPS_MODE` startup gate.
  - Operational changes include one-command gateway/Postgres/admin-UI startup, stronger backpressure and shutdown-flush behavior for spend records, and additional project/model rate-limit gauges.
- Key limits and upgrade risks:
  - The GitHub release aggregates a long development and backport interval rather than presenting a small curated migration guide. Some “What’s Changed” entries were later reverted or backported, so the main run should summarize only changes confirmed in the final tag.
  - Disabling stdio MCP by default can break existing local-tool deployments. Identity, guardrail, cost and Responses translation paths should be regression-tested together.
  - Several administrative features in the changelog are enterprise-only; do not describe the entire feature set as available in the community edition.
  - Suggested next action: keep `TRIAL`; upgrade in a production-shaped canary and test stdio MCP opt-in, remote MCP credential isolation, workload identity, request-local guardrails, budget accounting, streaming Responses, and rollback.
