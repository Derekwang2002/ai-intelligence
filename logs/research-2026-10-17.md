## 1. DeepSeek opens raw Search and Fetch APIs

**What changed.** DeepSeek exposed two bearer-authenticated endpoints for agents and RAG applications: `POST /v1/tools/search` returns structured search results, and `POST /v1/tools/fetch` converts one URL to Markdown. Search accepts 1–50 results, optional page content, localization and operators including `site:`, language and date filters. Results include a publisher-supplied `authority` tier and `rerank_score`; these are retrieval metadata, not independent truth labels.

**Price and operational limits.** Both endpoints cost $0.75 per 1,000 successful requests. Search is billable only when HTTP 200 returns a non-empty results array; Fetch only when it returns page content. Failed requests, empty searches and timeouts are not billed. Each API has a separate 5 QPS account limit, and Fetch also has per-domain rate limits. Calls made as server-side tools through DeepSeek Harness, Claude Code and Codex are free now, with billing scheduled to start at `2026-10-31T16:00:00Z` (`2026-11-01 00:00` Beijing).

**Why it matters.** The per-successful-request price is materially lower than many bundled search tools and makes it easy to separate retrieval cost from model tokens. A useful `TRIAL` action is to replay one RAG/agent workload, measure usable-result rate and Fetch success rate, audit content attribution and prompt-injection handling, and estimate spend under the 5 QPS cap. DeepSeek's statements about index size, traffic scale and spam filtering are vendor claims; no independent relevance or safety evaluation was found in this pass.

## 3. Dory1.0-4B exposes an elastic-depth small-model tradeoff

**What changed.** NVIDIA's 4B Dory model reuses a 20-layer recurrent block between 8-layer input and output blocks. Operators choose one, two or four loops from one checkpoint, spending more compute per token for higher task accuracy without swapping models. Its last-loop KV mode overwrites the recurrent cache between loops, holding KV memory near the one-loop footprint. The release provides BF16, MXFP8, native-NVFP4 and Q5_K_M GGUF formats, 256K context and tool-call examples.

**Evidence and limits.** NVIDIA reports SWE-bench Verified 50.3 / 59.5 / 61.8 across one/two/four loops and Terminal-Bench 2.1 at 12.5 / 18.1 / 22.2. All numbers are vendor measurements; several comparison columns are marked as externally reported, and internal Artificial Analysis estimates may differ from the official benchmark. The runtime path is early: vLLM support is under review, while llama.cpp requires a pinned fork; therefore this should not be described as production-ready despite downloadable weights.

**Suggested judgment.** `TRIAL` is defensible only with a one-day loop-count experiment: use the GGUF or pinned reference path on the same small coding/tool suite, then compare success rate, end-to-end latency, generated tokens and peak memory at one/two/four loops. Otherwise use `WATCH` until upstream vLLM or llama.cpp includes released support.

## 5. OpenAI opens text-described GPT-Live voices to all API customers

**What changed.** `/v1/audio/voices` can now create and save a GPT-Live voice from a plain-language description; no reference or consent recording is needed for this prompt-generated path. The changelog also adds nine natural voices across German, French, Hindi, Japanese and Korean. Voice generation itself is free, while listening or production speech is charged as a regular GPT-Live session.

**Boundaries that change the product decision.** Prompt-generated voices work only in GPT-Live. They do not work in the Text-to-Speech API, Realtime API or Chat Completions audio. Organizations can save at most 100. A chosen voice cannot be changed mid-session, voices are not guaranteed unique, children’s voices are disallowed, and voice creation is incompatible with Zero Data Retention even though GPT-Live speech can be ZDR-eligible. Recorded voice cloning remains limited to eligible customers and requires consent plus a matching sample.

**Suggested merge.** Add this as a material GPT-Live change to `ev-20260910-05`, keeping `TRIAL`: generate two constrained voices, test accent/style drift, disclosures, interruption behavior and session cost, then verify data-retention requirements before storing any voice.

## 6. Claude Code 2.1.302 fixes duplicate scheduled work after partial failure

**What changed.** The most consequential fix for long-running automation is that a scheduled routine which failed partway is no longer restarted from the beginning an hour or more later, a behavior that could repost the same report or repeat external side effects. The release also stops unsafe worktree cleanup, fixes lost config writes, restores MCP tools when a 2026-07-28 server omits optional-looking response metadata, and improves cloud-run status accuracy and reconnect behavior.

**Suggested merge.** Update `ev-20260814-04`, not a new event. Keep the established recommendation but rewrite the action to regression-test a scheduled side-effecting routine across crash/retry boundaries and confirm no duplicate message, issue or report is emitted.
