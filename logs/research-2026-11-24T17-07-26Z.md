## 1. RoboTrack — qualifying late discovery

**Primary sources**

- [Ai2 GitHub repository](https://github.com/allenai/robotrack)
- [RoboTracker weights](https://huggingface.co/allenai/RoboTracker)
- [RoboTracker-Warp weights](https://huggingface.co/allenai/RoboTracker-Warp)
- [RoboTrack-Bench dataset](https://huggingface.co/datasets/allenai/RoboTrack-Bench)
- [RoboTrack-15M training dataset](https://huggingface.co/datasets/allenai/RoboTrack-15M)

**Time basis**

- The official README labels the public release `2026/11/23` but does not give a time.
- The GitHub initial-release commit is timestamped `2026-11-23T06:42:15Z`, before the previous checkpoint.
- The Hugging Face benchmark was last modified at `2026-11-23T21:13:51Z`, inside this run's window; the model and training-data artifacts were finalized earlier on November 23.
- Treat this as a previous-run miss recovered from its post-cutoff manifest lead. Persist the official date precision and mark `late_discovery: true`; do not claim the whole release first became public at the benchmark's later modification time.

**Verified release facts**

- Ai2 released the benchmark, training data, two trackers, training/evaluation code and downloadable weights.
- RoboTrack-Bench contains 307 real robot and human manipulation clips with 2,522 hand-annotated point tracks. The sources include DROID, MolmoAct2, EgoVerse and Ego-Exo4D.
- RoboTrack-15M contains 3,000 simulated Franka-arm videos across 300 ProcTHOR houses, with 15 million point tracks; the repository lists a 17 GB download.
- RoboTracker is an AllTracker fine-tune and is Apache-2.0. RoboTracker-Warp is based on CoWTracker, is roughly 1B parameters, and its weights are CC-BY-NC-4.0. RoboTrack-15M uses ODC-BY; the benchmark includes component-specific access and licensing requirements.
- The authors report RoboTracker-Warp at 65.98 AJ on RoboTrack-Bench versus 63.87 for their CoWTracker baseline. They report about 2.5 hours for a full benchmark run on one H200; this is author-run evidence, not an independent reproduction.
- The repository explicitly warns that point tracks can fail under long occlusions or on textureless surfaces and should not directly drive robot motion without validation, bounded control and supervision.

**Editorial judgment**

- Suggested disposition: `new-event`, `Research`, likely `TRIAL` if the next action is a one-day reproduction using the public benchmark and checkpoints; otherwise `WATCH` is defensible because there is no independent evaluation yet.
- Why it matters: it makes a previously weak part of robot perception testable against real manipulation video, while shipping enough artifacts to reproduce the publisher's comparison.
- Limitation to preserve: benchmark performance is publisher-reported; the strongest model has a non-commercial license; the benchmark mixes robot and human manipulation clips and is not evidence of safe closed-loop robot control.

## 2. NVIDIA Sirius tutorial — new tutorial, older product release

**Primary sources**

- [NVIDIA tutorial dated November 23](https://developer.nvidia.com/blog/get-started-with-gpu-accelerated-duckdb-analytics-using-the-sirius-core-extension/)
- [DuckDB 2.0.1 LTS release announcement dated November 20](https://duckdb.org/2026/11/20/announcing-duckdb-201)
- [Sirius source repository](https://github.com/sirius-db/sirius)
- [DuckDB Sirius documentation](https://duckdb.org/docs/2.0/core_extensions/sirius)

**Time and stage finding**

- NVIDIA published a hands-on tutorial on `2026-11-23`; the page gives date precision only.
- The actual availability change happened on `2026-11-20`, when DuckDB 2.0.1 shipped Sirius as a core extension. Therefore the November 23 page must not be written as the Sirius launch or as a new GA transition.
- DuckDB says the extension is available on Linux x86-64 and arm64, requires an NVIDIA GPU with CUDA 12 or 13, detects the CUDA version on first load, downloads an approximately 1 GB backend, and falls back to DuckDB's CPU engine for unsupported queries.

**New evidence in the tutorial**

- NVIDIA reports cold-run TPC-H-derived tests from 100 GB to 10 TB, with tuned two-GPU configurations delivering 3.25x to 5.50x speedups over the best CPU configurations it tested and up to about 79% lower query-time compute cost.
- The comparison used pinned development builds. Sirius timings exclude result fetch/export while DuckDB CPU timings include CSV output. Cost excludes startup, validation, storage, S3 and idle time. Those asymmetries prevent treating the headline figures as a neutral end-to-end benchmark.

**Editorial judgment**

- Suggested disposition: if DuckDB 2.0.1/Sirius is absent from the event library, `new-event` as an important older omission is defensible only under recall/self-audit recovery, with `published_at` tied to November 20 and `late_discovery: true`. If the task limits recall recovery to the post-cutoff lead itself, use `filtered` for the November 23 tutorial because it adds vendor benchmark detail but no new availability stage.
- Recommendation should be `TRIAL`, not `ADOPT`: a one-day check can install DuckDB 2.0.1 plus Sirius on representative Linux/NVIDIA hardware, record which production queries fall back to CPU, and compare end-to-end runtime and total cost with fetch/export and startup included.

## 3. Tencent OmniEVIE-4B — qualifying in-window open-weight discovery

**Primary sources**

- [Hugging Face model card and weights](https://huggingface.co/tencent/OmniEVIE-4B)
- [Tencent code and technical report repository](https://github.com/Tencent/OmniEVIE)
- [MMEB leaderboard referenced by the model card](https://huggingface.co/spaces/TIGER-Lab/MMEB-Leaderboard)

**Time basis**

- The official Hugging Face repository was created at `2026-11-24T03:16:57Z` and last modified at `2026-11-24T13:17:25Z`, both inside the scan window.
- Tencent's GitHub repository was created at `2026-11-24T03:09:40Z` and pushed through `2026-11-24T13:16:55Z`.
- No separate company blog announcement or arXiv record was found during this check. The artifact publication itself is the verified release event.

**Verified release facts**

- Tencent IMA Product Center and Tencent Youtu Lab released a 4.54B-parameter, Qwen3.5-based multimodal retrieval model with weights, inference/indexing code, checksums and a technical-report PDF under Apache-2.0.
- It embeds text, natural images, visual documents and native video. A late-interaction multi-vector index can return the matching page region or video interval, rather than only a document-level match.
- The compressed configuration caps each record at 128 int8 vectors of 64 dimensions. Tencent lists a footprint of at most 9,472 bytes per record and 8.82 GiB per million records; a smaller K32 configuration is listed at 2.15 GiB per million pages.
- Tencent reports 54.2 ms search across one million records and 120.2 ms across five million records on one CPU thread after GPU encoding. It also reports 60.68 for the full model and 60.06 for the compressed model across MMEB-V3's 190 tasks.
- The model card's comparisons and latency tests are publisher-run. The leaderboard snapshot confirms a submitted result, not an independent reproduction. No hosted API or price was found; current use is self-hosted through Tencent's Python package and requires `flash-attn>=2.7.0`.

**Editorial judgment**

- Suggested disposition: `new-event`, likely `TRIAL`. It is directly relevant to multimodal RAG and ships public weights plus code, so a bounded one-day test is possible.
- Suggested next action: index a small mixed corpus of PDFs, screenshots and short videos; measure recall/nDCG, index size, GPU encoding time and CPU query latency against the team's current text and visual retrievers. Verify that localization is correct, not merely that the parent document ranks highly.
- Limitation to preserve: all performance numbers are Tencent-reported, support currently depends on a custom model/package path, and there is not yet independent evidence for production reliability or framework integration.
