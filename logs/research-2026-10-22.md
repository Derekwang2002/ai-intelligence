### 2. Recursive released Flint, an open-weight sparse coding model, with first-party Ollama support

- Primary sources: [Ollama v0.40.8 release](https://github.com/ollama/ollama/releases/tag/v0.40.8), [Ollama Flint library page](https://ollama.com/library/flint), [Recursive Flint model card](https://huggingface.co/RecursiveSI/flint)
- Public time basis: Ollama stable `v0.40.8` was published `2026-10-21T16:20:30Z`, inside the strict window. The model artifacts were available when checked during this run.
- What is verified: Flint is a 39.8B-parameter MoE model with about 2.5B active parameters per token and a 262K context window. Recursive publishes BF16 weights under Apache-2.0. The model card supplies SGLang and vLLM instructions; Ollama 0.40.8 adds a roughly 23 GB local package.
- Availability / constraints: the Ollama release currently calls out macOS support and says support for other GPUs will follow. Recursive says a single H200 or B300 is sufficient for BF16 serving. The Hugging Face card says Transformers modeling code is not yet included. Quantized variants exist, but quality parity was not independently established.
- Performance evidence: Recursive reports 54.9% on Terminal-Bench 2.1, 89.7% on SWE-bench Pro v2, and 74.2% on SWE-bench Verified. These are publisher-run results, use at least five attempts for some pass@1 reporting, and are not directly interchangeable across harnesses. No independent reproduction was found. At capture, the Hugging Face page showed 453 likes but only about 420 monthly downloads, so adoption is too early to infer.
- Suggested disposition: `new-event` / `TRIAL`. A one-day trial can run the published Ollama or vLLM artifact on a fixed coding-task set and compare patch validity, latency, memory, and repeated-run variance against the team's current model.
- Existing event ID: none found. The existing Ollama decision-model event `ev-20260928-09` is not the same release.

- Suggested disposition: `new-event` / `TRIAL`. Use the public code and weights for a one-day temporal-split test on one internal relational prediction task; check leakage, schema transfer, AUROC/MRR, GPU memory, and serving latency against the incumbent tabular baseline.

### 8. A document-ingestion study measured severe loss when formatting carries policy meaning

- Primary source: [Silent Cue Loss in Enterprise Document Ingestion](https://arxiv.org/abs/2610.30026)
- Public time basis: arXiv announced the submission during the strict window on 2026-10-21; the feed timestamp observed during this run was within the 16:17–17:55Z batch. The public record gives date-level confidence plus the feed boundary; do not invent finer paper-page precision.
- What is verified: the authors test 76 real policy documents with a deterministic matcher and six models, and separately analyze prevalence in 6,460 documents. They report formatting-blind micro-F1 falling from 0.690 to 0.150 with Docling conversion and 0.075 with plain-text conversion.
- Plain-language concept: “silent cue loss” means a parser keeps the words but drops visual signals such as highlighting or color that change the policy meaning; retrieval can look healthy while the answer is wrong because the decisive cue vanished before the model saw it.
- Evidence limits: no public code or reproducible artifact was found. The results are research evidence, not proof that every document pipeline loses cues at the same rate.
- Suggested disposition: `new-event` / `WATCH`. It is actionable enough to add formatting-preservation tests to RAG ingestion, but the lack of public artifacts caps it at WATCH under §16.2.
- Existing event ID: none found.

## Editorial shortlist

The strongest reader-facing candidates are:

1. OpenAI Usage Policies update — immediate architecture/vendor-risk relevance, with the crucial limitation that it is announced now but effective November 20.
2. Recursive Flint — genuinely downloadable open weights and practical Ollama/vLLM routes, but benchmarks remain publisher-reported and current GPU support is constrained.
3. Qwen Code 0.26.0 — material operational update to an existing event, especially recovery receipts and deployment preflight.
4. NVIDIA Kumo Relational — public code and weights make a bounded trial possible; claimed gains still need independent or internal reproduction.
5. Ai2 OlmoEarth v1.3 — unusually complete public artifact/data package released just before the cutoff, with a material custom-license constraint.

Microsoft Flint-interactive and the silent-cue-loss study are strong alternates if the final brief favors agent UI/RAG reliability over domain-specific geospatial tooling. TorchNeuron should be updated in the event library because the code is now public, but the contradictory public-beta/closed-beta wording should keep it out of an unqualified availability headline.

## Coverage limitations

- Some official feeds expose a precise timestamp while linked article pages expose only a date. Where only a date was durable, this note preserves that lower precision and does not claim hour-level certainty beyond the observed feed boundary.
- No independent reproductions were found for Flint, Kumo Relational, OlmoEarth v1.3, VocabX, or the research-paper claims in this pass.
- GitHub/Hugging Face counters are volatile snapshots and should not be treated as audited adoption data.
- Public documentation may lag rollout state. TorchNeuron is the clearest conflict: public source is verified, but official pages disagree on whether service access is public or closed beta.
- Search and source access were sufficient for the cited pages, but the lack of a discoverable repository/license for Flint-interactive and of public code for several papers is itself part of the disposition, not proof that no artifact can exist anywhere.
